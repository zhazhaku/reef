## 方向 2：独居者晨昏线

**1. 目标用户 & 场景故事**
72 岁的李阿姨独居在北京老小区，女儿在上海工作。每天早上 7 点，床头设备自动刷新显示"早安李阿姨 | 今天阴转小雨 8-15°C | 💊 降压药 1 片 降糖药 1 片"。如果上午 10 点阿姨还没按键确认吃药，设备用温和的女声说"李阿姨，该吃药了"。如果中午 12 点仍无确认，reef server 给女儿发飞书消息。

**2. 核心创新点（vs 小爱/xiaozhi/电子价签/Kindle）**
- 独有点 1：**不打扰的监视 vs 摄像头监控**。子女想确认老人安好，但摄像头侵犯隐私、电话打扰休息。晨昏线通过一个无害的"吃药看板+早安晚安问候"形态，自然地获得老人的日常活动信号（早/晚按键确认），子女只在异常时才收到告警——隐私感和安全感兼得。
- 独有点 2：**自适应节奏 vs 僵硬闹钟**。普通药盒定时响铃，不管老人是否已起床。晨昏线通过 reef LLM 学习老人按键模式（通常在 7:05-7:15 确认 → 正常；今天 8:00 还没确认 → 可能睡过头不舒服），差异化升级提醒策略。

**3. 用户体验流（按时序写）**
- 平时：屏幕大字显示时间 + 日期 + 天气 + 当日服药清单（24 小时常亮不灭，老人无需解锁任何设备）
- 触发：老人按一下床头按键（早晨确认起床 + 吃药 / 晚上确认已到家）
- 设备响应：屏幕局刷更新确认状态 → "✅ 已服药 7:12" + 药名旁打勾。如果晚于 8:00 未确认 → TTS 温和提醒"李阿姨，降压药还没吃哦"
- 收尾：全天每 30 分钟刷新时间。晚上 9 点自动显示"晚安 | 明天小雨记得带伞"并记录当天所有确认时间戳到 reef server

**4. reef swarm 如何赋能（2 个具体场景）**
- 场景 A：reef server 持续记录李阿姨的按键时间戳。LLM 分析 30 天数据，发现阿姨周二总是服药晚 1 小时（因为周二去菜市场）→ 自动调整周二提醒时间为 8:30。**设备学会适应老人的节奏，而非强迫老人适应设备。**
- 场景 B：女儿在 reef server 管理面板看妈妈这周的吃药记录。发现"周三未确认"，用手机 APP 发语音"妈，昨天是不是忘了吃药？"→ reef server dispatch `display_text` + `tts` 到阿姨的设备。阿姨听到女儿声音，按按键说"吃过了，放心"→ 语音转文字回传给女儿。

**5. xiaozhi 在其中的角色**
**A. 仅语音入口**。日常静默，仅在超时警告时 TTS 播报提醒，或女儿远程发语音时播放。reef-client 驱动所有 ePaper 显示和按键交互。

**6. 可行性自评**
- 屏幕日刷新次数：约 5-10 次（起床更新 + 确认更新 + 晚安更新 + 每小时时钟局刷）
- 续航估算：30-60 天 / 1000mAh（Wi-Fi 只在需要时连接，深度睡眠占大部分时间）
- MVP 工作量：15-20 人天
- 主要风险：老年用户体验打磨——字体必须极大（200×200 分辨率下中文至少要 24px 即约每行 8 个字）、按键手感、音量大小。需要至少 3 轮真实老人测试。
